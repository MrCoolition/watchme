# WATCHMÉ

A private, dial-first watch collection and design studio. Six original live watches, curated customization, saved collections, chronograph, countdown, dual time, weather, and a distraction-free display.

## Front & center and the Atelier

Phones open with the watch face enlarged and the bracelet removed. **Front & center** opens an immersive display with an optional edge-to-edge dial, large digital time/date, watch switching, lume, and opt-in keep-awake. **Face only / Full watch** controls the regular preview; display choices are remembered on the current device, separately from saved watch designs.

The Atelier offers six one-tap looks: After Hours, Icebreaker, Solar Flare, Royal Velvet, Deep Space, and Stealth. Each can be refined with polished, fluted, iced or ceramic bezels; carbon, meteorite or guilloché dials; black ceramic cases; five lume colors; sweep or tick seconds; and a custom dial signature. Looks preserve case architecture and complications, participate in undo/redo, and become permanent only when explicitly saved.

These additions are optional fields on `WatchDesign` version 1. Existing saved designs preserve their original rendering; no database migration is required for the new parts.

## Stack

Next.js App Router, React, TypeScript, Tailwind CSS, layered SVG, Neon Postgres with Drizzle, and iron-session. `main` controls the existing `watchme` Vercel project.

## Private setup

1. Install Node 24 and run `pnpm install`.
2. Run `pnpm setup` and open `http://127.0.0.1:4319`. Enter a private passphrase of at least 14 characters and a development-scoped Neon connection.
3. The local form stores only a salted scrypt hash, a generated session secret, and the connection in ignored `.env.local`. It never stores the plaintext passphrase. Close the setup process after use.
4. Confirm the Vercel project is linked to `MrCoolition/watchme` and configure the environment variables below before database-dependent testing.
5. Run `pnpm db:migrate`, then `pnpm dev`.

The application fails closed if private setup is incomplete. There is no public registration, default password, demo login, or production authentication bypass.

| Environment variable | Purpose |
| --- | --- |
| `neon_connect` | Server-only Neon connection; preserve this exact lowercase name |
| `WATCHME_PASSWORD_HASH` | `scrypt:saltHex:hashHex`, generated by local setup |
| `SESSION_SECRET` | Random session encryption secret of at least 32 characters |
| `WATCHME_SCHEMA` | Optional strict override: `watchme`, `watchme_preview`, or `watchme_dev` |

Without an explicit schema override, `VERCEL_ENV=production` selects `watchme`, preview selects `watchme_preview`, and local development selects `watchme_dev`. Use a scoped database role/connection for development and previews. Never broaden production credential access without explicit approval. Existing production `neon_connect` is a sensitive Vercel secret and cannot be retrieved through the environment API.

Set the hash and session secret through Vercel's encrypted environment settings for the intended environment; never put credentials in source, screenshots, chat, or logs. Changing the passphrase hash invalidates existing sessions. Changing `SESSION_SECRET` also signs devices out.

## Development and verification

```sh
pnpm lint
pnpm test
pnpm build
pnpm typecheck
pnpm test:e2e
```

Unit tests cover date/timezone boundaries, design compatibility, timers, passphrase/session validation, and authenticated endpoints. The isolated browser harness tests the real UI with test-only action doubles; it does **not** prove Neon connectivity. Verify save/reopen from two real authenticated browser contexts on a configured Vercel preview before production release.

## Deployment

Push a feature branch for a Vercel preview, verify it, then merge to `main`. Vercel runs `pnpm deploy:build`: it verifies the database and applies idempotent, additive schema creation when all credentials are configured, then builds Next.js. Missing setup produces a locked application and skips migrations. Migrations only touch the selected WATCHMÉ schema; they never drop tables or modify unrelated schemas.

The application uses the existing `watchme` Vercel project. Avoid creating a replacement project or database. Keep Vercel's deployment protection in place. After release, verify authentication, create/save/reopen/delete, weather, and API authorization on the production URL.

## Behavior and limits

- Watch configuration and preferences sync through Neon. Drafts, stopwatch, laps, and countdown state remain on the current device.
- Time follows the device clock and chosen IANA zones. A manually changed system clock affects restored timers.
- The full-screen display works in-page on all supported browsers. Native fullscreen and screen wake-lock are enhancements that can be denied by the browser or operating system.
- Countdown completion sound requires a user gesture and a running page. Closed-app/background alarm delivery is not guaranteed.
- Weather uses Open-Meteo with city search or explicit geolocation. Cached data is labelled stale after refresh failures; weather attribution appears in the interface.
- All case shapes and designs are original WATCHMÉ graphics. Curated layouts prevent complication collisions.
